# MediaGrab

A fast, cross-platform **video & audio downloader** built with **Flutter/Dart** —
one codebase targeting **Android, iOS, Windows, macOS and Linux**. Inspired by
apps like Snaptube.

> ⚠️ **Use responsibly.** Only download content you own or have the right to
> save, and respect each platform's Terms of Service and applicable copyright
> law. YouTube and most social platforms restrict downloading in their ToS.

## Architecture

```
lib/
├── main.dart                     App bootstrap (services + provider)
├── core/theme.dart               Material 3 theming
├── models/                       Plain data models
│   ├── media_source.dart         Supported platforms enum
│   ├── media_format.dart         One downloadable quality/format
│   ├── media_info.dart           Resolved media + its formats
│   └── download_task.dart        A persistent, resumable job
├── services/
│   ├── platform_detector.dart    URL → platform
│   ├── extractor_service.dart    Routes a URL to the right extractor
│   ├── extractors/               Pluggable resolvers (one per platform)
│   │   ├── extractor.dart        Extractor interface
│   │   ├── youtube_extractor.dart
│   │   └── direct_file_extractor.dart
│   ├── download_manager.dart     Streaming download + pause/resume
│   ├── notification_service.dart Progress notifications
│   └── storage_service.dart      Persists the queue (shared_preferences)
├── providers/download_provider.dart  App state (ChangeNotifier + provider)
└── ui/
    ├── screens/ (root, home, downloads, settings)
    └── widgets/ (format_selection_sheet, download_tile)
```

**Extensible by design:** adding a new platform means implementing one
`Extractor` subclass and registering it in `ExtractorService`.

### How pause / resume works
Downloads stream to disk with `dio`. On resume the manager checks how many
bytes already exist on disk and requests the remainder with an HTTP
`Range: bytes=<offset>-` header, appending to the file. The byte offset is
persisted with the task, so a paused download resumes even after the app is
killed and reopened.

### Enabling social platforms (Facebook / Instagram / TikTok / X / Vimeo)
These platforms use short-lived, signed stream URLs and often require session
cookies, so resolving them reliably on-device is brittle (and against their
ToS). The app ships with a resolver hook: point
`ExtractorService.resolverEndpoint` at your own micro-service that accepts
`{ "url": "..." }` and returns `{ title, author, thumbnail, duration, formats }`,
and those platforms light up without touching the app.

### MP3 conversion
"MP3 (audio)" saves the best audio track (`.m4a`). True MP3 transcoding needs
an ffmpeg step (e.g. the `ffmpeg_kit_flutter` package) — wire it into
`DownloadProvider.download` after the file completes.

## Building the installable files

Native platform folders (`android/`, `ios/`, `windows/`, …) are **generated by
CI**, not committed, so the repo stays lean and version-agnostic.

### In CI (recommended — produces the APK automatically)
Every push runs [`.github/workflows/build.yml`](.github/workflows/build.yml),
which:
1. Scaffolds the native folders with `flutter create`.
2. Patches Android permissions (`tool/patch_android.sh`).
3. Runs `flutter analyze` + `flutter test`.
4. Builds **split-per-ABI APKs**, a **universal APK**, an **App Bundle**, and a
   **Windows** build, uploading them as workflow **artifacts**.

Download the APK from the **Actions → latest run → Artifacts** section.
Pushing a tag like `v1.0.0` additionally publishes a **GitHub Release** with all
installable files attached.

```bash
git tag v1.0.0 && git push origin v1.0.0   # -> Release with APK/AAB/Windows zip
```

### Locally
Requires the [Flutter SDK](https://docs.flutter.dev/get-started/install) (3.24+).

```bash
flutter create --platforms=android,ios,windows --org com.mediagrab --project-name media_grab .
bash tool/patch_android.sh
flutter pub get
flutter run                       # run on a connected device / emulator
flutter build apk --release       # -> build/app/outputs/flutter-apk/
flutter build appbundle --release # Play Store bundle
flutter build ios --release       # macOS + Xcode signing required
flutter build windows --release
```

## Roadmap / MVP notes
- YouTube + direct links are fully functional in the MVP.
- Social-platform resolving is stubbed behind the backend hook above.
- True background (device-idle) downloads can be upgraded via `workmanager`
  or a foreground service; the current manager keeps downloading while the app
  is running/minimized and persists state for resume.
